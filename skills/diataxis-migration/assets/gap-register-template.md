# Documentation gap register

Record gaps that remain after the requested changes. Give each a stable ID within this audit and preserve the evidence that supports its status.

| Gap ID | Source evidence | Current implementation | Missing documentation | Target category | Status | Follow-up reference |
| --- | --- | --- | --- | --- | --- | --- |
| `GAP-001` | `[path, symbol, migration, test, commit, or unavailable source]` | `[observed behavior, or NOT VERIFIED]` | `[specific missing fact or procedure]` | `[Tutorial / How-to / Reference / Explanation / unknown]` | `[Fixed / Open documentation gap / Open implementation issue / Deferred verification / Superseded / Not applicable]` | `[issue, PR, or none]` |

Keep implementation defects separate from documentation gaps. Do not classify planned behavior as current merely to close an entry.

Suggested statuses include: Fixed; Open documentation gap; Open implementation issue; Deferred verification; Superseded; and Not applicable.
